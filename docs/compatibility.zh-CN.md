# 自动兼容是怎么判断的

[English](compatibility.en.md)

不需要选择版本。每次打开存档，工具会先检查能否解密和完整解析，再逐类检查编辑器实际要用的物品数据与存档字段。

| 遇到的变化 | 处理方式 |
| --- | --- |
| EXE 与参考版本不同 | 自动定位候选密钥，用存档目录的认证信息验证；不执行 EXE，也不单凭版本号拒绝 |
| 密钥位置移动或密钥内容变化 | 在已识别的 PE 区段内有限查找；只有认证成功才采用 |
| 物品表数值、文本或条目数量变化 | 检查属性布局、行数、ID 和类别所需字段；通过则读取当前数据 |
| 某一类物品结构变化或资源缺失 | 该类别停止添加、修改和移出，保留其他已通过检查的类别。已铸魂的主武器和影之武装仍可只清除 AlreadySnapSoul |
| 地图解析失败 | 停用地图分类，保留搜索和物品分类 |
| 文字或部分图标不可用 | 保留原始名称或 ID；图标失败不阻止编辑 |
| 存档容器版本变化，但旧布局仍可完整解析 | 仅供查看，禁用编辑、写回与恢复备份 |
| 无法解密、结构无法完整解析 | 显示原因并停止，不进行写入 |
| 打开后游戏文件再次更新 | 暂停写入，重新打开后再检查 |

读取成功后，保存仍需经过操作校验、候选文件完整回读、无关槽保护、源文件变化检查和自动备份。高级 ID 添加与另存副本也遵守类别检查，不能绕过它。

“格式检查通过”不等于“所有游戏效果都验证过”。例如新版本可能保留字段名，却改变了等级或任务规则。未做游戏回读的版本会在界面说明；当前实机参考环境仍是 Steam build 26266538。

开发者补充规则时，需要验证实际字段语义和游戏回读，不能只替换指纹。配置仅存放资源指纹、属性编号布局和密钥定位参考，不包含密钥或玩家数据。
